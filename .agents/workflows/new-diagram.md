# New Diagram

Create or update one diagram in `docs/design/diagrams/`.

1. Ask which diagram (use-case, class-domain, sequence-pay-bill, sequence-refund-failed, state-payment, er-diagram, or an extra). Ask only if I did not say.
2. Read `docs/requirements.md`, `docs/design/specs/state-transitions.md`, `business-rules.md` and any existing diagrams.
3. List the elements you plan to include (classes, states, actors, messages) in a short bullet list. Wait for my OK.
4. Write the source file with the header comment (purpose, date, related US/FR ids).
5. Check the syntax renders. State how you checked, or say you could not.
6. Compare names and flows against the other diagrams and specs. List every mismatch and fix the ones inside this file.
7. Draft a prompt-log entry marked `DRAFT: verdict pending` with the mistakes you found in your own first version.
